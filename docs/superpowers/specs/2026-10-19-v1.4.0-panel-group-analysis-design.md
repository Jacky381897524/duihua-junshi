# V1.4.0：面板内设置、逐句判断与群聊

状态：用户于 2026-10-19 回复“是”，已确认设计；执行计划待审阅。

本文件是下一版的可审阅设计，尚未实施产品代码。以现有 V1.3.11 为基础；保留既有版本与安装包，不发布或覆盖 GitHub 旧 Release。

## 1. 目标与范围

此次统一发布为 **V1.4.0**，Android versionCode 从 29 增至 30。

1. 修复面板内回复风格设置的闪退、对象选择、昵称带入和按钮尺寸；重新整理视觉层级。
2. 面板中的回复风格、悬浮窗和模型设置均在当前面板完成，不启动软件页面。删除面板菜单的完整咨询、连接诊断入口；主页原入口保留。
3. 用简短的意图、行动建议和带颜色的等级替换现有冗余说明；候选详情改为短句分块。
4. 新增“判断分析”：读取之后，选择一条对方/群成员消息，查看基于上下文的逐句判断。
5. 加入微信、QQ、抖音原生群聊。沿用前面确认的多话题六候选方案，也支持选定一条消息后围绕该消息生成六条候选。
6. 预留记忆与关系估计接口。本次不启用实时好感度，也不显示默认或虚构的好感度分数。

保留现有普通悬浮球、胶囊锁定/缩放、轻毛玻璃、减少动效、宽而薄的收起区域、缓存清理、专属优先于全对象风格等能力。

## 2. 当前证据与待核实项

### 已由代码和截图确认

- 回复风格编辑器的两个底部按钮沿用紧凑按钮，最小高度被清零，同时使用 wrap_content，因此被压成细条。
- 对象选择使用系统 Spinner。截图中有昵称输入，但下拉首项固定显示“添加 / 当前对象”，没有把当前对象作为清楚的可选记录呈现。
- 面板菜单的悬浮窗、模型、完整咨询和诊断仍调用 startActivity，尚未实现面板内设置流程。
- 当前解析、视觉提示、会话累计、持久化、判断与生成多处限制 DIRECT 和最近 50 条；群聊需要贯穿这些环节，不能只开放页面分类。
- 候选详情接口返回自由文本，界面直接显示，缺少段落层级。
- Jev 原始参考客户端已有 choice.probabilities、noul 和 score 的解析方式，可以复用其真实返回结构，不需要在界面中编造示例百分比。

### 尚未由真机日志确认

本次 ADB 未检测到设备。Spinner 的实际崩溃堆栈、系统是否拦截页面启动，以及昵称未带入的具体失败样本，仍待设备验证。对下拉框的处理将改为同一面板中的对象列表，不再依赖外部弹窗。

## 3. 架构选择

推荐继续使用原生 Android View，在现有悬浮窗口中加入页面栈，复用设置校验、接口与加密存储。备选是每项设置使用独立悬浮窗口，但会增加窗口令牌、键盘焦点和返回键的生命周期组合；本版采用同一窗口方案。

组件职责：

- **面板页面栈**：候选、菜单、回复风格、对象列表、悬浮窗设置、模型设置、模型选择、判断消息列表、判断详情。负责返回、滚动位置、编辑状态和焦点。
- **原生表单组件**：Activity 与悬浮面板复用设置业务逻辑。下拉选择、模型搜索均在面板内部展示。
- **会话上下文**：明确平台、会话类型、群/联系人标题、消息发送者、原文、引用、消息 ID 与内容版本。
- **判断服务**：Jev 协议解析、逐句判断、结果校验和缓存，不负责窗口跳转或修改聊天正文。
- **候选协调器**：区分普通六候选、群聊多话题候选、指定消息候选，拒绝过期结果。

不整体更换 UI 框架，不引入 WebView 面板，不持续截图或后台轮询聊天。

## 4. 面板内设置

### 4.1 回复风格

- 顶部为标题与返回入口。专属/全对象使用清晰的分段选择。
- 默认进入“当前对话专属”；显示平台、当前昵称、是否已保存专属风格。
- 昵称从当前窗口读取结果自动带入。已有手动读取结果必须通过新截图标题指纹和会话范围核对才可复用；没有可靠结果时在本机识别标题，允许粘贴校正。
- 当前对象直接显示完整昵称，不再用模糊的“添加 / 当前对象”作为唯一标识。
- “关联已有对象”打开面板内可搜索列表；没有记录时显示空状态，不创建系统 Spinner 弹窗。
- 只有点击保存才创建或更新专属记录。校正的识别别名在确认后关联，冲突时要求核对，不覆盖其他对象。
- 专属风格和全对象风格均可直接保存。专属优先于全对象，未匹配使用全对象。
- 保存按钮最小高度 48dp，返回按钮最小高度 44dp；大字体可增高。文本区可滚动，键盘出现后仍能滚动到保存区。
- 颜色、边距、输入框、选项和辅助说明统一适配深浅主题。
- 昵称、风格和别名继续加密存于持久数据区，清除缓存不删除。

### 4.2 悬浮窗设置

在面板内设置轻毛玻璃、胶囊入口、胶囊位置重置、锁定/缩放、普通球自动隐藏秒数、减少动效及填入后行为。保存外观或入口变化时保留当前聊天上下文，不跳转 Activity；需要重建外层窗口时恢复面板位置与已读状态。

### 4.3 模型设置

保留回复、视觉、判断三类设置及现有服务预设、自定义地址、密钥、模型目录、手动 ID 和连接测试。表单、模型搜索和选择都在面板内完成。

- 密钥默认遮挡，不写入日志或错误提示。
- 打开设置不自动请求网络；刷新目录和连接测试由用户点击。
- 请求绑定表单修订号和页面生命周期；切服务、返回或修改配置后不接收旧请求结果。
- 保存沿用原有校验和加密存储，配置变化后旧候选失效，提示重新读取/刷新。
- 主页面已有设置入口仍可使用，两边读写同一配置。

## 5. 候选面板内容

布局顺序：

```text
•••
军师分析                          更多  收起
等级：一般 · 5/9            判断分析  读取信息
对方真实意图：更可能希望你给出具体安排
建议：先确认可行时间，再回应她关心的细节       1–3 / 6

候选卡片：策略、适合程度、正文、复制/填入/详情
刷新换一批 · 6条
────────────────────────────────
                  ⌃
```

- 删除“六种方案，滑动选择 · Jev 为适合程度”的固定说明，改为判断后的意图。
- 删除“候选回复 · 六种思路”的固定说明，改为判断后的行动建议。
- 意图和建议分别最多两行，使用简短文本；完整内容在判断分析中查看。
- 表述显示“更可能/可能”等推测含义，不把模型判断写成已经证实的内心事实。群聊多话题时显示当前群聊焦点，指定成员消息时显示该成员的意图与建议。
- 等级保留 1–9 数值，1–3 为绿色“安全”，4–6 为橙色“一般”，7–9 为红色“危险”，颜色随数值向红色过渡。结果未知时显示“待判断”，不使用绿色默认值。
- 面板不再显示“风险”一词；协议与旧存储内部字段可保留以兼容旧配置。
- 读取、生成、失败提示继续明确显示，不被意图或建议覆盖。

### 候选详情

展开后默认显示短句分块：

1. **为什么这样说**：一句。
2. **适合现在吗**：一句适用条件。
3. **注意什么**：一句实际代价或边界。
4. **对方接下来**：积极、含糊、拒绝各一行，分别给出简短做法。

使用结构化返回与长度限制，不把自由文本整段塞入卡片。失败有重试入口；折叠/展开只操作当前卡片，返回结果必须仍属于同一候选和同一会话。

## 6. 判断分析

### 入口与选择

- 在“读取信息”左侧添加“判断分析”。
- 尚未读取有效对话时呈禁用外观；点按只反馈“请先读取信息，才能判断分析”，不发起请求。读取中、会话失效或已切换对象时同样拦截。
- 有效读取后，在面板内展示本次可用上下文中全部对方消息。单聊按时间顺序显示；群聊额外显示成员昵称。
- 每项显示消息原文、引用标记和消息类型。引用是所选消息的背景，不算另一条新发言。语音没有转写时不猜测其内容。
- 用户点选一条后才请求该条判断，不为所有消息同时发起请求。默认列表定位最新一条对方消息。

### 判断上下文与排版

默认按所选消息及其之前已经读取的上下文判断，避免拿后续结果倒推当时意图。明确显示“基于这句之前已读取的对话”；如有上下文缺失则在结果中说明。

结果使用图3类似的短卡片：

- **选中的原话**：成员与正文，引用另列。
- **表面意思**：是否主要按字面理解。
- **更可能的意图**：按 Jev 返回的权重排序，最多三项。
- **更需要你做什么**：如理解情绪、解释、采取行动、具体安排，最多三项。
- **建议动作**：一句主要建议，可补充一条应避免的做法。
- **等级**：沿用绿色至红色等级条。
- **判断依据**：引用一至两处实际已读原文；不能编造历史。

百分比只显示接口真实提供且校验有效的分布或模型估计，标为“模型判断权重”。缺失时显示文本判断与“未提供权重”，不补造 72% 等数值；分数、置信度、选项分布不混用。判断不足时允许“信息不足”。

在判断详情中可返回消息列表；群聊另有“围绕这句给我六条回复”，调用指定消息候选流程。原来的“最后一句是我说的”规则继续约束普通候选，不把我的最后一句改判成对方。

### 请求与缓存

结果绑定平台、会话、内容版本、所选消息 ID、判断配置修订号。切对象、重新读取、选择另一条或修改模型后，旧请求即使完成也不能覆盖当前结果。缓存相同上下文与同一目标的结果，页面重开不重复请求；提供明确重试，不无限自动重试。

## 7. 群聊

### 读取与身份

- 支持微信、QQ、抖音的原生群聊天窗口；评论、直播、QQ频道、网页和图片里嵌套的聊天截图仍不算当前会话。
- 右边是我；左边每条绑定其可见群成员昵称。不能把所有左侧消息合并为同一个人。
- 保留原文、顺序、引用、可见成员和文字/图片/表情包类型。背景文字和头像内容不作为聊天正文读取。
- 会话类型结合实际页面与成员标识判断，不仅凭标题末尾的括号数字判为群聊。确认属于群成员计数的数字与风格匹配名分离；群名本身的数字不删除。
- 对不可确认的成员标注“成员未识别”，不凭头像或相似昵称拼成同一人；可以保留可读消息作为有限上下文，并提示识别缺失。
- 边缘裁切的残缺消息不作为整次读取不可靠的理由；跳过或标注该条，不补字、不把裁切片段当完整原话。

### 上下文范围

群聊默认最多保留最近 **100 条已读取上下文**，可设置 50 / 100 / 200。单聊既有 50 条行为保留。

这里的数量是已读取上下文的上限，不意味着单屏能读到 100 条：只取得当前可见消息和此前手动读取累计的内容，不自动翻群历史，不在未读取时声称拥有历史。

网络请求必须实际使用设置范围内的可用上下文，不能界面显示 100 条而仍固定只发送 50 条。若服务上下文容量不足，应明确提示调整范围，不能悄悄删除消息后声称已分析全部。

累计、去重和历史恢复比较发送者、原文、引用及会话类型；同名不同群或无法确认的窗口不强行合并。单聊与群聊的缓存、风格、候选目标分开。

### 两个候选流程

1. **自动接话**：读取后识别近期主要话题，生成总共六条候选，可分配给不同话题。每条显示“回复谁 / 接哪句或哪一话题”，复制或填入前就能看清目标。
2. **指定消息**：从已读消息中选择一条，生成六条都围绕该条的不同回法。返回自动接话后恢复多话题方式。

群聊不强制加入恋爱、暧昧或邀约策略；按实际群聊关系选择接话、澄清、安排、幽默或边界表达。候选引用的成员和消息 ID 必须来自已读记录，不能由模型编造。

填入写入普通输入草稿，由用户检查并发送。本版不自动 @、不自动引用微信消息、不自动发送。

### 群聊风格

优先级为“此群专属 → 全部群聊风格 → 自然群聊风格”。群聊不继承某个成员的单聊专属风格，也不默认套用单聊的恋爱表达偏好。群聊菜单内同样可编辑并保存。

## 8. 记忆与好感度的扩展准备

本次只形成可扩展数据边界：

- 会话范围：平台、单/群、会话标识和标题。
- 参与者：当前可见昵称和会话内标识，不引入账号/头像匹配。
- 证据：来源消息 ID、原文、时间、内容版本、是否引用及识别来源。
- 推断：判断类型、模型、版本、依据、可选置信度、未知项与生成时间。
- 后续记忆仓库接口：明确区分可证实事件、用户确认事实与模型推测，并允许撤销。
- 后续关系估计接口：区分成员/联系人/群、估计范围、依据与未知状态。

未来功能可以复用上述结构，但 V1.4.0 不默认启用长期记忆写入、不后台监控聊天，不把 OCR 或模型猜测直接写成已确认事实，也不在界面放一个看似真实的好感度百分比。

## 9. 性能与回归约束

- 模糊继续交给原生合成器，列表按需构建，较长消息可展开，避免在拖动和动画每帧重复全量测量。
- 设置打开、保存本地选项和返回不产生模型请求；逐句判断按点选请求，缓存可复用结果。
- 耗时读取、解析和网络操作在后台执行；返回时可取消，所有回调核对范围。
- 保留当前填入的窗口、编辑器、会话和草稿验证；不把填入失败悄悄当作成功。
- 原始特殊昵称完整保存；同一平台完全同名对象仍需不同备注，不能凭昵称区分实际账号。
- 沿用 Android 11+、ARM64 的现有安装范围及签名，正常覆盖安装保留本地配置。

## 10. 实现拆分与验收

实现拆分围绕同一个 V1.4.0 安装包进行：

1. 面板页面栈、内嵌选择列表、表单尺寸及昵称自动带入。
2. 悬浮窗/模型内嵌设置与生命周期。
3. 意图/建议、等级颜色、结构化候选详情。
4. 逐句判断结构、Jev 解析、列表/结果、过期回调与缓存。
5. 群聊读取、发送者、上下文累计、话题/目标候选、群聊风格隔离。
6. 版本/更新记录、编译、签名、旧版保留和真机验证。

验收必须覆盖：

- 对象列表展开不闪退；当前昵称、关联已有对象、专属/全对象保存与缓存清理后的持久保存。
- 保存/返回按钮尺寸、深浅色、大字体、窄屏、键盘遮挡和返回键。
- 每项面板设置可在聊天上完成；不启动软件主页。
- 顶部两个短文本不超过各两行，等级不显示“风险”且颜色正确。
- 详情分块、折叠、请求失败与重试。
- 未读取时判断反馈明确；选不同消息、切聊天/模型、锁屏后的旧结果不串用。
- Jev 分布缺失、无效数字、不完整响应时不伪造百分比。
- 三个平台群聊的多成员/同名成员/多话题、引用、特殊昵称、背景文字和边缘裁切。
- 单聊最后一句为我时，六条仍接着我的话；群聊目标 ID 有效，不把他人发言合并。
- 多话题与指定消息切换、50/100/200 上下文、专属/全群风格隔离。
- 复制/填入只写草稿，不触发发送、@或原生引用。
- 完整核心与配置测试、Android 编译与静态检查、安装包签名/内容/16KB 本地库校验；设备不可用时明确列出未完成的真机项目，不把编译通过当作实际可用性证明。

用户审阅本设计后再写执行计划并进入实现；若用户调整群聊规则或历史判断上下文，先同步到本文件。
