# V1.7.12 keyboard and candidate retention

Base: V1.7.11, commit `85d350d466db7774240db3d97c6515893ae786d0`. Android versionCode 59, versionName V1.7.12.

## Evidence and diagnosis

The two supplied screen recordings show a populated candidate panel becoming empty in the same chat around keyboard/composer interaction. This task did not receive a new diagnostic export. The recordings establish the visible failure, not the device's exact native/OCR callback sequence.

Source inspection found two reproducible geometry errors and an incorrect invalidation condition:

- Native header selection used fractions of total available window height. A title at y=115..190 was accepted at height 2344 but rejected after the keyboard reduced height to 1500/1100, despite unchanged title coordinates.
- Screenshot header/fingerprint mapping scaled vertical coordinates using bitmap-height / window-height. During an IME transition, unchanged screenshot pixels with shortened window metadata moved a 120..288 title sample to 200..481, into the chat body.
- A changed pixel fingerprint plus missing title was promoted to a navigation check. That check could invalidate an otherwise live successful batch. Pixel differences alone do not establish a new contact.

These geometry cases failed against V1.7.11 and pass with this patch. Android documents that keyboard visibility can resize the available application area: [Handle input method visibility](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility).

## Changes

- Keep native title/header traversal bands independent of available height, using the window width.
- Use one width-derived pixel scale for local title crops and toolbar fingerprints, with bounds checks for scaled/short screenshots and split-window origins.
- Keep actual Activity/window navigation separate from header pixel changes. A passive missing-title result retains the live batch; a confirmed different title still restores its own cache or displays the unread state. Explicit navigation to an unreadable contact still withholds the old batch. Fill verification is unchanged.
- Widen the WeChat local title crop to accommodate long remarks; reject edge-clipped OCR words as new names.
- Log numeric screenshot and viewport dimensions for local OCR. No raw titles, messages, screenshots or keys are added to diagnostic/source uploads.
- Correct an existing device-test fixture to alternate missing/matching titles. A genuinely different full title must continue to switch ownership rather than be treated as the same contact.
