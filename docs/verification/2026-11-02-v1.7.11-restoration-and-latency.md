# V1.7.11 verification

Base: V1.7.10. Android versionCode 58, versionName V1.7.11.

## Observed failure

The supplied diagnostic contained a successful six-candidate publication followed about 0.56 seconds later by `CACHE_HEADER_OCR_MISS` and `CACHE_TITLE_MISS`, with visible result count zero. The sequence repeated after another successful generation. The cache reported ten entries and six repeated-name rows; the repeated-name counter rose after a fresh read. Screenshot and model requests succeeded. This establishes a local restoration failure after generation, not a failed generation or evidence of a service crash.

The title matcher rejected a spelling if it appeared more than once in the supplied cache-name list. Duplicate cache rows were thus confused with different spellings or an unreadable title. Cache records were not consolidated when they shared the exact title and full viewport evidence but lacked the text-overlap threshold (for example, short messages and images). Repeated Activity focus events and a rigid status-bar origin could also revoke a live panel before a reliable title decision.

## Changes and checks

- Title lookup deduplicates identical spellings while retaining actual spelling collisions and owner disambiguation checks.
- Same platform, chat kind, title, header fingerprint, dimensions and conversation fingerprint can consolidate identical captured reads, including loading older records. Different names or body fingerprints do not merge on title alone.
- Local header OCR covers both system-bar-present and system-bar-absent screenshot origins. The identified title's actual text row calibrates the subsequent fingerprint, rather than relying indefinitely on a fixed band.
- Identical Activity/window focus notifications are not treated as new navigation. Confirmed same-title passive checks retain the live batch; actual navigation continues to require ownership checks.
- Same-content rereads reuse the assessment despite new message IDs and observation timestamps. The key retains roles, senders, quotes, message kinds, actual message-time data, target position, background, personal context, judge configuration and date. Reuse expires after two minutes.
- The original drafting, judging, quality policy and context are retained. Duplicate custom-judge instructions were removed; fixed generation rules precede changing context for prefix-cache opportunities.
- UTF-8 request bytes are encoded once and sent with fixed content length. This follows [Android's HttpURLConnection upload guidance](https://developer.android.com/reference/java/net/HttpURLConnection), avoiding the implementation's additional whole-body buffer.

604 core tests pass with zero failures, errors or skips. The debug APK and Android instrumentation test APK compile successfully. Instrumentation was not executed on the user's device. Regression coverage includes duplicate-cache loading, full-image duplicate consolidation, changed-body separation, repeated Activity focus, title OCR with and without a system-bar row, actual-title fingerprint geometry, same-content reread reuse, changed-background invalidation, original rule/role/target contracts, and UTF-8 Content-Length against a local HTTP server.

## Performance limits

The supplied two successful generation sequences took approximately 4.676 and 4.953 seconds, excluding their preceding visual reads. The two judging stages together took approximately 2.0 seconds. These are historical observations, not measurements of the new APK. The controlled reuse test confirms one fewer judgment request for an unchanged reread; no fixed real-world speedup or unchanged model-output quality score is claimed. No paid live model benchmark was performed. OEM screenshots, continuous contact switching and actual model/network latency still require device validation.

Raw diagnostics, video frames, real user conversation text, credentials and signing keys are excluded from source synchronization.
