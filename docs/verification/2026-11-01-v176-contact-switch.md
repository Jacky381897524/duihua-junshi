# V1.7.6：连续对象切换

## V1.7.5 日志

- 截图成功后，标题 OCR 多次未能匹配缓存，产生 `CACHE_TITLE_UNVERIFIED`；也有标题特征匹配成功的记录。单凭这些脱敏日志不能确定每次 OCR 未匹配的原因。
- 候选缓存写入有 `COUNT=10` 的记录。旧日志的 `CACHED` 是 0/1 标记，不是缓存对象数量，不能将 `CACHED=1` 解读为仅保存了一个对象。
- 多次模型请求返回 HTTP 402。当次生成没有新的成功批次；不能据此确定服务商具体账单状态。
- 旧版近期会话匹配要求新画面尾部整段位于旧画面中；末尾新增消息时可能无法复用已知身份，从而产生重复记录。这是可复现的代码缺陷，日志未包含昵称，不能证明它是本次所有失败的原因。

## 修改与验证范围

- 近期会话改为查找唯一的双向连续重叠片段；短而常见的对话和多个可能对象仍不自动合并。
- 在加密候选缓存中额外保存可见聊天区域的本地指纹；同名或标题像素变化时，仅在指纹唯一且图像具有足够细节时尝试恢复。切换核对不保存原始截图，也不因切换上传截图或调用模型；手动读取仍按原有视觉设置工作。旧版记录无此指纹，需在安全核对后逐渐建立。
- 生成新候选前，对已确认身份恢复上一批；生成失败保留此前成功批次。诊断记录真实缓存数量、同标题重复数量、有效聊天指纹数量，不记录昵称或聊天正文。
- 面板按钮行高和内边距收紧；紧凑菜单的表达模式高度与回复风格按钮一致。

应在真实手机上验证展开面板连续切换七个对象、同名对象、界面变化和截图受保护场景。指纹或标题均无法唯一确认时不能保证自动恢复，避免把另一人的候选当成当前对象。
